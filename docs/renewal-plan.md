# Jaspr リニューアル調査・方針

更新日: 2026-07-31

## 目的

現在のシンプルなプロフィールサイトを、Dart / Jaspr で構築する個人ポートフォリオへ更新する。
外部サービスに分散している自己紹介、活動、制作物を見つけやすくしつつ、更新負荷を増やしすぎないことを重視する。

## 調査した対象

- 現行サイト: <https://blendthink.github.io/>
- 公開 Notion「履歴書」: <https://blendthink.notion.site/d9624d9360544b3bbf97074ec1706ce7>
- Dart 公式サイト: <https://github.com/dart-lang/site-www>

## 現状

### 現行サイト

- Kotlin/JS と Compose HTML で構築された単一ページ
- プロフィール画像、氏名、短いメッセージ、X / GitHub / Speaker Deck へのリンクのみ
- 黒背景を中心とした、情報量を抑えた名刺的なデザイン
- プロフィール画像から Notion の履歴書へ遷移する
- コピーライトが 2022 年で固定されている

良い点は、本人を識別しやすく、目的の外部リンクへすぐ移動できること。一方で、得意領域、現在の活動、制作物、登壇などがサイトだけでは分からない。

### 公開 Notion

次の情報が集約されている。

- 自己紹介、特徴、好き・苦手
- キャリアプラン（短期、中・長期）
- 基本情報、資格・免許
- 略歴
- 登壇歴
- 本業・副業の職務経歴
- OSS 活動歴
- ソーシャルメディア

内容は充実しているが、履歴書としての詳細情報と、初めて訪れた人が知りたい概要が同じ階層にある。データベース表示は公開ページで読み込めない場合もあるため、サイトの主要コンテンツを Notion の表示や API に依存させない方が安定する。

### Dart 公式サイトの Jaspr 構成

2026-07-31 時点の `dart-lang/site-www` は、主に次の構成を採用している。

- Jaspr の `static` モードで静的サイトを生成
- `jaspr_content` で Markdown / HTML コンテンツを読み込む
- server entry point でページ、レイアウト、Markdown 拡張、カスタムコンポーネントを登録
- client entry point は必要な操作だけを担当
- `components`、`layouts`、`models`、`pages` を分離
- SCSS を base / components / pages に分割
- コンテンツと UI 実装を分離し、大量のドキュメントを管理

個人サイトで同じ規模の仕組みは不要だが、次の考え方は参考になる。

- 静的生成を基本にする
- コンテンツとレイアウトを分ける
- 共通 UI を小さなコンポーネントにする
- ブラウザ側の Dart は必要な箇所だけで動かす
- ページが増える前提で URL とナビゲーションを設計する

## 推奨するサイト像

「Dart / Flutter を軸に、考えて作り、コミュニティへ還元するエンジニア」という人物像を、読むだけでなく触って感じられるポートフォリオにする。

一般的な履歴書サイトではなく、訪問者が小さな発見や反応を楽しみながら回遊できる「インタラクティブな個人サイト」を目指す。動きは装飾として一律に加えるのではなく、本人の思考、仕事、活動のつながりを伝えるために使う。

Notion の履歴書を完全に複製するのではなく、公開対象を編集して見せる。

### 情報設計

1. **Home**
   - 名前、肩書き、短いステートメント
   - 現在注力していること
   - 代表的な制作物・活動を 3 件程度
   - GitHub、X、Speaker Deck、メールへの導線
2. **About**
   - 自己紹介
   - 大切にしている考え方
   - 得意領域と使用技術
   - 好きなこと（人柄が伝わる範囲）
3. **Works / OSS**
   - DVM などの代表プロジェクト
   - OSS コントリビューション
   - 各項目に概要、役割、技術、リンクを付ける
4. **Talks**
   - 登壇を新しい順に掲載
   - イベント、タイトル、日付、資料リンクを持たせる
5. **Career**
   - 公開可能な粒度で要約したタイムライン
   - 詳細な履歴書が必要な場合だけ Notion へ案内する

初期リリースでは Home / About / Works の 3 ページでもよい。Talks と Career は、掲載データを整理してから追加できる。

### 掲載しない、または慎重に扱う情報

- 生年月日、年齢、性別、配偶者・扶養家族などの個人情報
- 契約上公開できない会社名、案件名、業務詳細
- 自己評価の弱点を履歴書からそのまま転載したもの
- 更新停止済みの履歴を「現在の活動」と誤認させる表示

## 体験コンセプト

### Engineer's House

サイト全体を、かわいいエンジニアの 3D キャラクターで探索する「大きなエンジニアの家」として設計する。
縦方向に決められた順序で読むページではなく、訪問者がキャラクターを動かし、部屋や物を調べながら blendthink の情報を見つける非線形な探索体験にする。

- 斜め上から見下ろすドールハウス風の 3D 空間にする
- キャラクターは歩く、走る、物を調べる、端末を操作するといった小さな動作を持つ
- PC、工作机、本棚、壁の写真、モニターなどを調べると情報が見つかる
- 部屋同士のつながりに本人の活動や思考のつながりを反映する
- 調べた物や訪れた部屋は家の見取り図に記録される
- 隠し扉、秘密のコマンド、特定の順番で反応する物などを散りばめる
- 季節、時刻、再訪回数などで小さな変化を加える
- すべてを見つけなくても主要情報へ到達でき、探索した人には追加の発見がある構造にする

プロフィール画像の雰囲気をキャラクターデザインへ引き継ぎ、本人の分身として扱う。写実的な人物ではなく、丸みがありシルエットで識別できるデフォルメキャラクターを想定する。

### Home の体験案

1. キャラクターが玄関または自室で起動し、近くの物が小さく反応する
2. 訪問者は床を選択するか、方向キー / WASD / スティックで移動する
3. 反応する物へ近づくと「調べる」合図が表示される
4. 調べると情報カード、作品、スライド、短い会話などがその場で開く
5. 新しい情報を見つけると、別の部屋への鍵やヒントを得られることがある
6. いつでも見取り図を開き、発見済みの場所と主要コンテンツを確認できる
7. 通常の一覧表示にも切り替えられ、目的がある訪問者は情報へ直接移動できる

スクロール位置に合わせて要素を順番に登場させる構成は採用しない。スクロールは詳細パネル内の文章を読む用途に限定し、サイト全体の進行は訪問者の選択と移動で決まるようにする。

実装初期は、一部屋、キャラクター移動、3 個の調査可能オブジェクト、1 個の隠し要素に絞る。これで操作感と「もっと探したい」と思えるかを検証してから家全体を作る。

### 部屋と情報の対応案

| 場所 | 見つかる情報 | 主なオブジェクト |
| --- | --- | --- |
| 玄関 | 自己紹介、サイトの遊び方 | 表札、靴箱、案内板 |
| 開発部屋 | Works、OSS、使用技術 | PC、複数モニター、端末、ホワイトボード |
| 書斎 | 考え方、学び、キャリア | 本棚、ノート、設計図、古い端末 |
| リビング | 好きなもの、人柄、日常 | 猫、ソファ、写真、甘い食べ物 |
| スタジオ | Talks、Speaker Deck、イベント | ステージ、マイク、プロジェクター |
| ガレージ / ラボ | 開発中のもの、実験 | 工具、試作品、エラー表示中の機械 |
| 屋根裏・地下室 | Easter egg、過去作品、秘密 | 隠し端末、古いディスク、謎の扉 |

### 隠し要素の案

- 本棚の特定の本を順番に選ぶと隠し扉が開く
- 端末に Dart の短いコードやコマンドを入力すると秘密の画面が起動する
- 猫について行くと通常は見えない通路を発見できる
- モニターの時刻やアクセスした日によって表示が変わる
- 家の中に Dart / Flutter に関係する小物や過去の技術を配置する
- すべての部屋で特定のアイテムを見つけるとキャラクターの衣装が増える
- Konami Code など、エンジニアが気付きやすい入力に反応する
- エラーになっている機械を直すと、開発中プロジェクトの情報が開く

## モーション方針

- モーションには位置関係の理解、発見のフィードバック、操作への反応のいずれかの役割を持たせる
- 大きな移動より、透明度、奥行き、わずかな追従を中心にする
- ポインターがないタッチ端末でも同等の情報へ到達できるようにする
- `prefers-reduced-motion` を尊重し、動きを減らしても意味や操作性が失われないようにする
- アニメーション開始前でも本文を読める構造にし、検索エンジンやアクセシビリティを損なわない
- 初期表示を妨げないよう、重い処理は読み込み後に開始する
- 常時動作する処理は画面外、非表示タブ、低性能端末で停止または軽量化する
- 探索空間内の各地点に URL を割り当て、共有、戻る操作、検索エンジンからの直接訪問を可能にする
- 探索 UI を使わなくても全情報へ到達できる一覧モードを用意する
- 移動だけで情報を取得させず、近づいた後に明示的な「調べる」操作を設ける
- 3D 酔いを避けるため、カメラは固定角度を基本とし、急な回転や揺れを使わない
- キーボード、タッチ、ポインターで同じ探索ができるようにする

## ビジュアル方針

- 現行の黒を基調とした雰囲気は残し、読みやすさのため明度差と余白を整える
- プロフィール画像と短い思想をホームの中心に残し、既存サイトとの連続性を持たせる
- アクセントカラーは Dart / Flutter を想起させる青系を候補にする
- 見出し、本文、補足の階層を明確にする
- モバイルを先に設計し、デスクトップではカードやタイムラインを広げる
- OS 設定に応じたライト / ダークテーマを検討する
- アイコンだけのリンクには必ずアクセシブルな名前を付ける
- 日本語を主言語とし、英語対応は URL 設計だけ先に妨げない形にする

## 推奨技術構成

```text
lib/
  main.server.dart
  main.client.dart          # 必要になった時だけ追加
  src/
    components/
      layout/
      common/
      sections/
    layouts/
    models/
    pages/
content/
  about.md
  works/
  talks/
web/
  images/
  icons/
  styles/
test/
```

- Dart / Jaspr の static mode
- コンテンツが複数ページになるため `jaspr_content` を利用
- 本文は Markdown、カードやナビゲーションは Jaspr コンポーネントとして管理
- CSS animation と Web Animations API を基本にし、状態やイベントは Jaspr のクライアントコンポーネントで管理
- 3D 空間は WebGL / Canvas の独立したクライアントコンポーネントとして実装し、Jaspr はページ、コンテンツ、ルーティング、HTML のフォールバックを担当
- キャラクター、家具、家は軽量な glTF / GLB アセットとして管理する
- 探索状態は URL とブラウザ内の保存領域に分け、共有可能な現在地と端末固有の発見履歴を区別する
- 静的 HTML を先に生成し、インタラクション部分だけをクライアント側で有効化する
- Works / Talks の繰り返しデータは、初期は front matter 付き Markdown または型付き Dart データにする
- GitHub Pages へのデプロイは GitHub Actions でビルド成果物を公開する
- Notion は一次データにせず、詳細履歴への外部リンクとして扱う

Notion API による同期は初期スコープから外す。自動同期には認証、データ変換、公開範囲の管理、ビルド安定性という追加コストがあるため、必要性が明確になってから検討する。

## 進め方

### Phase 1: 土台とホーム

- Jaspr static プロジェクトへ移行
- 共通レイアウト、ヘッダー、フッター、レスポンシブ CSS を作成
- Home を実装
- 一部屋、キャラクター移動、オブジェクト調査、隠し扉の縦切りプロトタイプを実装
- reduced motion とタッチ操作を含むフォールバックを実装
- SEO / OGP / favicon / アクセシビリティの基礎を整備
- GitHub Pages のプレビュー・デプロイを構築

### Phase 2: コンテンツ

- About と Works を追加
- Notion から公開対象だけを編集して移行
- Works の画像、説明、外部リンクを整備

### Phase 3: 活動履歴

- Talks と Career を追加
- 更新しやすいコンテンツ形式を検証
- 必要なら GitHub API 等から活動情報をビルド時に取得する仕組みを検討

## 最初に決めたいこと

- サイトの主言語を日本語のみとするか、日英対応を初期から行うか
- 「Dart / Flutter エンジニア」を前面に出すか、より広いソフトウェアエンジニア像にするか
- 職務経歴をどの粒度まで公開するか
- 代表作として最初に掲載する 3 件
- 現行の黒基調を継承するか、ライトテーマを主にするか

## 現時点の提案

最初の実装は、かわいい 3D エンジニアを操作して大きな家を探索するポートフォリオとする。体験コンセプトは `Engineer's House`。まず一部屋だけの縦切りプロトタイプを作り、移動、調査、情報表示、隠し扉までの楽しさを検証する。Jaspr は静的な情報構造と UI を担当し、3D 探索部分を独立したクライアントコンポーネントとして組み込む。詳細な履歴は Notion に残し、一覧モードからも主要情報へ到達できるようにする。
